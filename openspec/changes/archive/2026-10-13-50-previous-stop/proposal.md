# Proposal: 50-previous-stop

狀態：`proposed`
編號：50。依賴 Change 45／46（題型與卡片補發機制）已合入 main。

## Why
目前順序題只有「下一站是哪裡」（`NEXT_STOP_FORWARD`）。真實開車時，司機常常需要從終點方向、或在中途想起「我剛剛經過哪一站」，也就是**反向**的路線記憶。只練「下一站」會讓記憶偏單向。新增「**上一站是哪裡**」：給一個站，問它的前一站。

## What Changes
- **新題型 `PREVIOUS_STOP_BACKWARD`**：給站 B，答它在這條路線上的前一站 A。
  - 提示：B 的完整站名（與「下一站」題相同的呈現方式）；答案：A 的站名，用寬鬆站名比對（忽略大小寫、標點、縮寫差異），與 `NEXT_STOP_FORWARD` 一致。
- **新卡片 `PREV_STOP::{fromStopId}->{toStopId}`**：每一對相鄰站一張（與 `NEXT_STOP::` 同樣的鍵格式與方向，只是問的方向相反；路線第一站沒有前一站，所以不產生）。SRS 進度與「下一站」卡**各自獨立排程**。
- **新卡類型 `CardType.PREV_STOP`**、**新題型 enum 值**（Prisma + migration，兩個 `ADD VALUE`，只新增、向下相容）。
- **新報名**：開始練習時自動帶上上一站卡。
- **既有報名自動補發**（沿用 Change 46 機制）：`CURRENT_CARDS_VERSION` 1 → 2；下次開始練習時，只**新增**缺少的 `PREV_STOP` 卡，**絕不修改或重建既有卡片**，SRS 進度完全不受影響。
- 練習頁與 i18n（en／zh-TW）新增標籤；進度 DTO 為新卡投影 `currentSequence`。

## 設計取捨（請審）
1. **卡片數量會增加**：一條 N 站的路線，順序卡從 N−1 張變 2(N−1) 張。每次練習的「題數」（session size）不變，只是可抽的題庫變大、反向題會出現在複習佇列。若你覺得太多，可改成「只在司機答對下一站卡之後才解鎖上一站卡」（較複雜，不在本提案內）。
2. **相鄰站名相同時題目沒有意義**（例如同一站不同月台）：與現有「下一站」題相同的限制，本 change 不處理；若相鄰兩站的寬鬆站名相同則**不產生**該張上一站卡（避免提示即答案）。
3. **不做新的 cloze／提示變化**：提示就是站名本身，維持簡單。

## Non-goals
- 「上上一站」或任意跳站題、拖拉排序題。
- 修改既有 `NEXT_STOP` 題與其進度。
- 舊的非 session 提示路徑（`get-current-recall-prompt-use-case`，僅舊測試使用）。

## 風險與測試（TDD）
- **既有進度不得被動到**：補發只新增、不改既有卡（沿用並擴充 Change 46 的測試）。
- 卡片產生器、鍵格式解析（含站 ID 內含 `->` 之類邊界）、出題與批改共用同一推導、評分寬鬆比對、補發版本 1→2、新報名卡數、DTO 投影。
- 多個既有測試以「卡片總數」為斷言，會隨之更新（列在 tasks 的相關項）。
- 守門三綠：`eslint` / `vitest run --fileParallelism=false` / `next build`；並用真瀏覽器跑一次完整流程。
